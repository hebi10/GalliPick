# GalliPick 7-C — 파일 갤러리·검색·필터 정밀 보정

기준 원본: Google Drive의 GalliPick 9화면 디자인 시안과 7단계 비교 기획안.
실제 화면 기준선: PR #32 병합 후 7-B Android 캡처 5개 프로필(총 30개 MediaStore 테스트 미디어).

## 확인한 화면 차이
- 파일 화면의 기존 상단 한 줄에는 정렬/필터/추가 작업/보기 전환 버튼 뒤에 미디어 종류 칩이 배치되어 있었습니다. 360dp 화면의 실제 캡처에서는 사진 칩이 오른쪽에 부분 노출되고 동영상 칩은 화면 밖에 있었습니다.
- 원본 파일 목록은 종류 전환과 사진 그리드를 기본 작업으로 강조합니다. 현재 한 줄을 가로 스크롤해야 종류를 바꿀 수 있는 구조는 이 작업 위계와 다릅니다.
- 실제 30개 데이터 기준으로 적응형 3열 썸네일과 목록 전환·동영상 길이 표시·보호 표시가 작동합니다. 7-A의 한 종류 MP4 6개 복제로 인해 반복되는 영상 프레임은 디자인 결함으로 간주하지 않습니다.
- 전체 화면 필터는 미디어 유형/날짜/검색/폴더 그룹과 키보드 위 고정 적용 버튼이 실제 캡처에 표시됩니다. 새로운 조건이나 동작은 추가하지 않습니다.

## 7-C 구현
- F-03: '전체·사진·동영상' 종류 칩과 그리드/목록 전환을 첫 번째 도구 행에 배치. 세 칩은 동일한 남는 가로폭을 사용해 320dp·글꼴 160%에서도 동시에 접근할 수 있도록 합니다.
- F-02: 기존 3열 적응형 갤러리, 실제 썸네일, 재생 시간·보호 배지, 선택 후 하단 작업바는 유지합니다.
- FL-01~03: 기존 조건 섹션·날짜 범위·키보드 위 적용 버튼은 보존하고 기존 UI 테스트로 회귀를 검증합니다. 기능에 직접 영향 없는 추가 시각 요소는 도입하지 않습니다.
- 정렬/상세 필터/추가 작업은 두 번째 도구 행으로 배치해 종류 칩에 밀리지 않도록 분리합니다.
- 기존 FileToolbarTest 320dp·160% 검증에서 모든 종류 칩과 목록 보기 버튼이 실제 표시되는지, 도구 행 순서와 필터 보존 여부를 확인합니다.

## 검증 및 병합 조건
1. Android verification: 단위 테스트·Lint·빌드
2. Android device tests: 320dp·160%, 미디어 종류 전환, 정렬, 프리셋, 기존 파일 선택·보호 동작
3. Adaptive UI verification and native captures: 휴대폰 세로/가로/글꼴 160%, 태블릿 세로/가로의 실제 갤러리 및 필터 캡처
4. 실패 시 수정 후 재검증. 성공 시에만 main에 병합하고 실제 캡처 ZIP과 PR 상태를 Drive에 보관
5. 앱 package ID, versionCode, 서명, Play 배포·설정과 Android 휴지통 승인 흐름은 변경하지 않습니다.
