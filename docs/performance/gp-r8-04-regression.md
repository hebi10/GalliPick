# GP-R8-04 — 실제 최적화 APK 회귀 검증

## 자동화 범위

GP-R8-03 기반의 검증 브랜치. 운영 앱이 아닌 `com.hebi.gallipick.benchmark`, 동일 임시 키, 동일 커밋 및 versionCode를 사용하며 Firebase 구성과 광고는 비활성 상태입니다.

| 검사 | 완료 조건 |
| --- | --- |
| 동일 서명 업데이트 | 비최적화 APK에서 R8 APK로 `adb install -r`, 앱 데이터 초기화 없음 |
| 설정 및 Room | 기존 목록 보기 실제 UI, Room v8 무결성, MediaStore URI·보호 설정·SHA-256 캐시 보존 |
| WorkManager | 기존 성공 작업 ID 보존, R8 앱에서 새 중복 분석 Worker 및 OCR Worker 실제 완료. 중복 해시/세션 검증 |
| 사진/동영상 | 합성 사진 및 저장소 테스트 영상 파일 상세·미리보기·재생 동작 |
| OCR | 에뮬레이터의 CJK 폰트로 생성한 한국어·영문 합성 이미지에 대해 실제 번들 ML Kit 인식 결과 및 상태 검증 |
| 원본 보존 | 합성 원본 4개 파일에 대해 실측 SHA-256 비교. 분석 중 미디어 삭제/변경 없음 |

기존 기기 벤치마크를 한 번 실행한 뒤 같은 격리 에뮬레이터에서 별도 설치·업데이트를 실행합니다. 실제 미디어를 가져오거나 기존 사용자 데이터에 접근하지 않습니다. DB와 WAL은 앱 force-stop 후 복사본만 읽습니다. 모든 단계 통과 후 `play-cloud-device-metrics`의 `regression.json` 및 기존 `metrics.json`을 보관합니다. 보고서에는 개인 사진, 실제 계정, 구매 토큰, DB 원본을 저장하지 않습니다. 기존 테스트 증빙 및 배포 승인 정책은 변경하지 않습니다.

OCR 합성 이미지 생성에 FFmpeg의 `drawtext` 필터를 사용합니다. 기기 CI에서 FFmpeg가 없는 경우 Ubuntu 공식 패키지로 설치하고, 필터 지원까지 APK 빌드 전에 확인합니다. 앱 의존성이나 운영 설정은 변경하지 않습니다.

## 별도 검증이 필요한 항목

| 분류 | 필요 조건과 절차 | 합격 조건 |
| --- | --- | --- |
| 실제 이전 Play 버전 업데이트 | 테스트 계정과 Play 서명으로 설치한 이전 버전에서 동결된 최종 후보 업데이트, 데이터 초기화 금지 | DB/필터/프리셋/테마/보호 및 예약 작업 보존 |
| 기존 예약 작업 | 이전 버전에 OCR·중복·사진 분석 작업을 예약/일시정지하고 업데이트 후 실행, 별도 테스트 계정 자동 백업 예약 | 작업 이름 및 생성자 호환, 의도한 재개/중지, 중복 실행 없음 |
| 사진 분석 및 삭제/복원 | 합성 원본만 사용, 실제 시스템 승인 취소/허용 및 보호 파일 제외, 휴지통 이동 후 복원·원본 해시 검사 | 원본 보존, 사용자 승인 없이 이동 없음, 마지막 사본/보호 파일 삭제 차단 |
| Google 로그인 / App Check | Play 설치·테스트 계정, 유효/취소/계정 전환/토큰 만료 | 정상 로그인 및 접근 제어, 이전 계정 데이터 노출 없음 |
| Billing | 라이선스 테스트 계정/상품, 월·연간 구독 구매·취소·복원·권한 확인, 실제 청구 금지 | 서버 검증과 광고/클라우드 권한 일치 |
| AdMob / UMP | 공식 테스트 광고 및 동의 흐름, 광고 제거·보상형 광고 검증 | 중복 보상 없음, 동의 및 광고 제거 동작 |
| Cloud 백업/복원 | 승인된 격리 테스트 계정과 합성 원본, 업로드·다운로드·취소·네트워크 장애·계정 전환 | 원본 SHA 일치, 권한/용량·복원 보존 및 타 계정 격리 |

## 병합/배포 게이트

GP-R8-01~03 선행 PR의 최신 검증과 병합 순서를 유지하고, 이 PR의 자동 검증 결과 및 잔여 위험을 확인한 뒤 GP-R8-05/06으로 이동합니다. 운영 기능은 서명·테스트 계정·서비스 환경 없이는 성공 처리하지 않습니다. 실제 Play 내부 테스트 및 운영 서비스 변경은 별도 승인에 따른 절차로 진행합니다. 현재 코드는 테스트 구현이며 CI 결과 확인 전 테스트 성공을 의미하지 않습니다.
