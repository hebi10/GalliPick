## 배포 방식 및 결과 판단

1. 릴리스 PR에서 정확히 versionName 0.2.5→0.2.6, versionCode 16→17 변경과 문서·한국어 릴리스 노트 변경을 검증합니다.
2. 검증 통과 시에만, `main` 병합 커밋 메시지에 **단독 `[deploy-closed]`** 를 포함해 자동 배포를 실행합니다. `[deploy-internal]` 및 버전 태그 push는 하지 않습니다.
3. 배포 워크플로는 기존 원본 업로드키·pin 검증, Workload Identity 또는 기존 Play 인증, `alpha` 트랙과 업로드 최대 코드 재확인, Android 테스트, 서명 APK·AAB 검증 후 단일 대상 트랙에 업로드합니다.
4. 보고서의 `status=committed`, `mode=deploy`, `track=alpha`, `version_name=0.2.6`, `version_code=17`, `api_accepted=true`, `track_verified=true`가 확인돼야 **API 제출 완료**로 기록합니다.
5. Google Play의 심사 승인 및 테스터 설치 가능 여부는 API 수락과 별개입니다. [실기기 QA #40](https://github.com/hebi10/GalliPick/issues/40), [Play 심사·테스터 검증 #42](https://github.com/hebi10/GalliPick/issues/42)를 유지합니다.
6. 실패나 응답이 불명확하면 버전 17을 재제출하지 않고 결과 보고서·트랙 상태를 먼저 조회합니다.
