# GP-ADS-VIDEO-01 — 정리 분석 보상형 광고

기준 v0.2.26 (37). [#128 기획](https://github.com/hebi10/GalliPick/issues/128) 및 [통합 제품 정책](https://docs.google.com/document/d/1nm-znFD9MXNbmYSKqruEA2VkT-PMZusoL1VoevrD-8w/edit)의 Android 구현·검증 계약입니다.

현재 앱은 `GalliAdPlacement.HOME_BANNER`를 실제 광고 위치로 사용합니다. 중복·유사 사진·연속 촬영·선명도 분석은 검토 후보입니다. 기존 정리 기능의 기본 이용 범위를 검토하고 대상 분석 진입점을 확정한 뒤 보상형 광고를 연결합니다. 파일 열람, 권한 변경, 기본 정리, 시스템 휴지통 삭제·복원을 유료 구독이나 광고에 연결하지 않습니다. [AdMob 보상형 광고 정책](https://support.google.com/admob/answer/7313578) · [Google Play 광고 정책](https://support.google.com/googleplay/android-developer/answer/9857753)

## 진입 결정

| 조건 | 동작 |
| --- | --- |
| 대상 이외의 진입점, 보상형 광고가 꺼진 빌드 | 기존대로 분석 시작. 보상형 광고 요청 없음 |
| `VERIFIED_AD_FREE` | 서버가 현재 계정에서 확인한 Cloud·광고 제거 구독 또는 유효 이용권으로 바로 진입 |
| `VERIFYING` | 신규 시청 선택과 광고 요청 보류. 상태 재조회와 뒤로 가기 제공 |
| `NOT_PURCHASED`, 광고 빌드 설정과 SDK 준비 및 UMP 요청 허용 | 해당 분석 1회 이용 조건과 `광고 시청하고 이용`, `취소`를 표시. 클릭 시 요청 조건을 다시 확인 |
| UMP 요청 불가, 초기화 실패, 무재고 | 광고 없이 기존 기능으로 돌아갈 수 있게 하고, 대상이 확정된 추가 분석에 한해 다시 시도 안내 |

기존 `rememberGalliAdsSession`의 UMP·SDK 상태 및 `CloudAdPlanObservation.removalFor`의 현재 계정 검증을 재사용합니다. 계정 미연결과 기존 구독 확인 실패를 구별합니다. 홈 배너의 표시 조건은 그대로 두고 보상형 광고에는 별도 활성화 조건을 둡니다. 시험 빌드에서는 Google 공식 테스트 단위를 사용하고 운영 빌드의 보상형 광고는 별도 승인 전까지 비활성화합니다. [UMP 가이드](https://developers.google.com/admob/android/next-gen/privacy) · [Android Rewarded Ad 가이드](https://developers.google.com/admob/android/next-gen/rewarded)

## 한 번의 시청과 분석 세션

| 이벤트 | 결과 |
| --- | --- |
| 분석 선택 | 사용 조건 모달을 엽니다. 취소하거나 모달 밖으로 나가면 종료합니다 |
| `광고 시청하고 이용` 선택 | 현재 계정 세대, 분석 종류, 시청 시도를 묶습니다. 한 번에 하나의 요청만 진행합니다 |
| SDK 보상 콜백 | 같은 시도·계정·분석에만 한 번 보상을 기록합니다. 분석 화면은 전면 광고가 닫히고 앱이 다시 활성화됐을 때 엽니다 |
| 보상 전 중단, 로드·표시 실패 | 분석을 열지 않습니다. 재시도는 별도 선택을 받고 새로운 시도로 시작합니다 |
| 분석 중 비교·뒤로 탐색·화면 회전 | 같은 세션의 경로에서는 재시청 없이 탐색합니다. 화면 회전은 진행 중인 시청을 중복 요청하지 않습니다 |
| 분석에서 이탈, 로그아웃·계정 전환, 프로세스 재시작 | 시도 및 세션 접근을 폐기합니다. 이전 시도의 콜백으로 새 세션을 열 수 없습니다 |

분석 경로를 다시 여는 보상 사용은 한 번만 처리합니다. 이후 세션 내부 이동은 기존 경로 상태에서 처리합니다. 시청 시도와 보상은 프로세스의 메모리에만 유지하고 `SavedState`, 영구 저장소, 분석 로그에 저장하지 않습니다. 광고 클릭·노출·닫기만으로는 보상을 부여하지 않습니다. 시험에 사용하는 광고 소스의 보상·닫기 콜백 순서를 확인하고, 다른 순서가 가능한 광고 소스는 해당 순서의 보상 지급과 취소를 검증한 뒤 추가합니다.

## GP-ADS-VIDEO-02~03 확인 항목

1. **대상과 접근성**. 후보 분석의 실제 진입점과 광고 선택 없이 가능한 기본 기능을 기록합니다. TalkBack, 글꼴 160%, 뒤로 가기에서 조건·보상·취소를 확인합니다. 사진 선택·비교, 삭제·복원, 권한 승인, 결제, 클라우드 전송 중에는 새 광고를 열지 않습니다.
2. **광고 요청과 보상**. 공식 테스트 단위로 최초 선택, 완료, 닫기, 무재고, 로드 실패, 중복 콜백, 취소 후 늦은 콜백을 재현합니다. 기록된 보상과 실제 분석 진입의 횟수를 각각 확인합니다.
3. **계정과 화면 상태**. 미로그인, 무료, 광고 제거 단독, Cloud 구독, 확인 실패, 만료·복원, 계정 전환을 확인합니다. 시청 중 회전·백그라운드에서는 중복 요청을, 프로세스 종료 후에는 보상 재사용을 확인합니다.
4. **기존 동작**. `noAds` 및 일반 빌드, 배너 동작, 파일 열람, 기본 정리, 시스템 휴지통 승인·취소·복원을 검증합니다. 실제 광고 단위, Play 신고, AdMob·개인정보 설정을 검토한 뒤 운영 적용 여부를 결정합니다.

## 시험 빌드 연결 범위

`정리 → 비슷한 사진 찾기 → 추가 분석 결과 → 선명도 확인 후보 보기`에서만 시험 광고를 연결합니다. 사진 특징 분석의 시작·재개, 유사 사진과 연속 촬영 결과, 정리 검토함, 파일 열람, 권한 변경, 휴지통·복원은 기존 경로로 이용합니다. 일반 디버그 빌드, `noAds`, 모든 릴리스 빌드에서는 선명도 후보도 기존 방식으로 바로 열립니다.

연결된 Android 시험 기기에 아래 명령으로 Google 샘플 광고 전용 빌드를 설치합니다.

```bash
./gradlew -PgallipickTestSigning=true -PgallipickAdsTest=true -PgallipickRewardedAdsTest=true installDebug
```

기기에 분석용 사진을 넣고 후보가 발생한 상태에서 명시적 동의, 완료 후 화면 전환, 광고 닫기·실패 후 재시도, 화면 회전과 앱 전환을 각각 확인합니다. 실기기 계정 시험에서는 개발 Firebase가 연결된 빌드를 사용해 현재 계정의 광고 제거 혜택에 따른 즉시 진입과 계정 전환 후 이전 보상 폐기를 확인합니다. 광고 로드·시청 완료는 Google 공식 테스트 광고에서 직접 확인해야 합니다. 운영 광고 단위와 운영 활성화는 이 시험에 포함되지 않습니다.
