# 중복 정리 작업 기록

기준 원격: d48c396afca508051acfa6fbbde812b7517dbb96 (v0.1.2). 작업 브랜치 improve/duplicate-clarity-v0.1.6.

원래 로컬 v0.1.5 소스는 작업 공간 정리로 소실됐다. 공개 소스와 실제 전달 APK를 기준으로 기존 기능을 복원하며 이를 원래 커밋의 바이트 복구로 표현하지 않는다. v0.1.5 APK SHA-256은 45ea916bce6511e0fefab09ce47c7f49ae5d1d8bbf7f59fc89dc087677eb252e. 개인 서명 복구는 별도 비공개 경로에서 수행하며 공개 인증서만 추적한다.

구현: 테마·파일 도구·정렬·스크롤 헤더 복원, 중복 역할/개수/범위 표시, 묶음 선택과 남김 변경 정책, 창 크기에 맞춘 A/B 비교, 남김 사본 검토와 실제 처리 결과 확인 완료. 작은 창 영상 표시 영역과 재검증 중 창 닫기 경계도 반영했다. 독립 안전성·사용성·릴리스 검토에서 남은 P1/P2는 확인되지 않았다.

전환 전 개발 키의 로컬 빌드: 안내 메시지 갱신 보완 뒤 34초에 성공했다. Java17/Gradle8.13/SDK36, JVM82개 통과(실패/오류/건너뜀0), debug/release lint 오류0(경고17/15, hint각1), release APK와 Android 테스트 APK 생성 성공. 릴리스 보조 도구의 앞선 Python 검사18개도 통과했다. 당시 로컬 APK는 46,602,758 bytes, SHA-256 `fc19c2a1038e9f03ce9ce3bf42d354fc928ed7a33c6b0adc3c3cd72273264eb2`이며 v0.1.5 개발 키와 같은 인증서였다. 앞선 공개 대상130파일의 개인 키/비밀번호 누출 검사도 통과했다.

전환 전 원격 기능 검증: [PR #2](https://github.com/hebi10/GalliPick/pull/2)의 head는 `62d5543a4744e9e27412e124cf9d422aca9e1400`, 기준 Git 트리는 `81eb568ac626ba6ea52a606050c2796751d42eff`였다. 당시 원격 소스와 로컬 제품·테스트 소스의 일치를 확인했다.

Android API36 실행 이력:

- [41385906101](https://github.com/hebi10/GalliPick/actions/runs/41385906101): 46개 중45개 통과·1개 실패. 최종 확인 후 파일 변경 차단 검사에서 파일 불변·차단 문구는 확인됐으나 활성 접근성 패키지의 `android` 값 때문에 실패했다. 해당 logcat에는 외부 Activity 시작 기록이 없었다. 전경 패키지 단일 판정 대신 `ON_PAUSE` 0회·`RESUMED`·차단 문구 표시·파일 불변을 함께 확인하도록 테스트만 변경했고 독립 검토를 거쳤다.
- 추가 진단에서 구체적인 최종 재검증 차단 안내가 새로고침 중 `AppViewModel.publishMedia`의 일반 선택 해제 안내로 덮이는 제품 문제를 확인했다. 스크린샷에는 Quickstep(`com.android.launcher3`) 응답 없음 화면도 있었다. `MainActivity`에서 최종 재검증이 실패한 비복원 이동 요청의 선택을 구체적인 안내 설정·새로고침 전에 해제하는 한 줄 보완을 적용했고 독립 안전성 검토를 거쳤다.
- 테스트는 변경한 파일명이 반영된 새 카탈로그·조회 완료·선택 해제를 기다린 다음 정확한 차단 문구, 파일의 휴지통 미이동 상태, Activity 생명주기를 확인하도록 보완했으며 진단을 유지한다. CI는 `--no-daemon` 빌드를 기기 부팅 전에 끝내고 Launcher만 종료하도록 조정했다.
- [최종 API36 41389091080](https://github.com/hebi10/GalliPick/actions/runs/41389091080): 46개 통과/실패·오류·건너뜀0, 104.602초. 실제 시스템 캡처는 정확한 차단 안내가 유지되고 Quickstep ANR 창이 사라졌음을 보여 준다. `ON_PAUSE=0`, `RESUMED`, 활성 창은 앱 패키지이며 일반 선택 해제 안내는 없다. [최종 빌드·단위·lint 41389091073](https://github.com/hebi10/GalliPick/actions/runs/41389091073)도 성공, JVM82개 전부 통과 및 CI lint 오류0(경고27·hint1), Python18개 통과다. 두 실행은 동일 head를 검증했다.

개발 키의 게시 시도: PR2를 main에 병합했고 커밋 `3725e8d6ae67a38ed4a422eb7382c5c9c57b0ce0`의 트리가 기능 검증 트리와 동일함을 확인했다. 사용자 승인으로 기존 개발 키의 복구 자료를 Actions secret에 등록했다. main `4b274885c175bc91afc821a197a1c0dc1a21c674`의 [공개 릴리스 41392108200](https://github.com/hebi10/GalliPick/actions/runs/41392108200)는 사용자 JKS 제공 후 게시 job 전에 취소했다. 태그·초안·공개 릴리스는 생성되지 않았다.

사용자 제공 JKS 전환: 아직 공개한 앱이 아니므로 제공 키를 새 기준으로 사용하도록 승인받았다. JKS 무결성·개인 키·서명 챌린지를 비공개로 확인했으며 공개 인증서 SHA-256은 `3da9245ec543bba6348541e60346ebe8ed296bc0fb09eea4ae763138204d1bb1`이다. 실제 비밀번호·별칭·개인 경로는 기록하지 않는다. 복구 ZIP은 공통 3파일과 `gallipick-signing.jks`로 만들고 서로 다른 저장소·개인 키 비밀번호 및 원본 바이트를 유지한다. 이전 PKCS12 형식 지원과 현재 서명 인증서의 동일성은 구분한다.

현재 JKS 기준 로컬 검증: 12초 빌드 성공, JVM82개·debug/release lint 오류0·release 및 Android 테스트 APK 생성·메타데이터와 새 인증서 확인. Python JKS 검사25개와 키스토어·설정 바이트를 유지하는 4파일 복구 검사도 통과했다. 새 로컬 APK는 46,602,758 bytes, SHA-256 `0c2c164b5bd9ffa0b5e9a5a8fe2a093ac4ad49107fafac275bda69d43fcdee6c`다.

남은 단계: 새 공개 지문과 JKS 복구 지원 소스를 반영하고 새 기준의 CI·공개 릴리스·다운로드 검증을 수행한다. 새 JKS 복구 자료의 Actions secret 갱신 요청은 GitHub의 추가 본인 확인 창에서 대기 중이며 아직 저장 완료가 아니다. 사용자가 해당 계정 인증을 완료하면 갱신 여부를 확인하고 새 소스로 릴리스한다. 아직 새 기준의 원격 CI·공개 게시 통과를 주장하지 않는다. 기존 개발 키의 v0.1.5·이전 v0.1.6 시험 설치본은 한 번 재설치해야 하며 로컬 설정이 초기화될 수 있다. 앱 데이터 이전이나 서명 키 회전 증명은 구현하지 않았다. 개인 키는 공개 소스나 릴리스에 올리지 않는다.
