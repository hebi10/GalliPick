# GalliPick 12-C — 스마트 정리 검토함

기준: 12-B가 병합된 main(b4875c2), 기존 앱 v0.2.9 / code20.
구현 브랜치: feature-12c-smart-review-inbox-20261109

## 정보 구조
- 기존 상위 4탭을 유지한다.
- 정리 > 사진 검토함으로 진입한다. 사진 분석을 하지 않은 경우 사진 분석 화면 이동 버튼을 보여 준다.
- 현재 접근 가능한 유사 사진·연속 촬영 묶음을 하나의 검토함에서 확인한다.
- 홈의 '사진 검토 이어서'는 유효하게 저장된 검토 상태 중 완료하지 않은 묶음이 있을 때에만 표시한다.

## 주요 상태
- 사진별: 검토 전 / 남김 / 정리 후보 / 검토 보류.
- 묶음별: 검토 전 / 이어서 검토 / 보류 / 검토 완료. 전원이 남김 또는 후보일 때에만 완료.
- 상단: 전체 묶음 수, 완료/미완료, 개별 상태 수와 진행률.
- 사진 비교: 기존 12-A A/B 동시 비교로 이동하고 검토함으로 돌아올 수 있다.
- 묶음 간 탐색: 목록 → 상세 → 다음 묶음. 휴대폰은 한 열, 태블릿은 목록·상세 2열.

## 저장 및 안전
- Room 별도 photo_review_choice 테이블에 묶음 ID, 사진 URI, fingerprint, volumeVersion, 상태, 수정 시각 저장.
- 기존 Room v6→v7 명시적 마이그레이션. 기존 이미지 캐시, 보호, 휴지통 이동/복원 내역은 보존.
- 실행 시 현재 접근 가능한 MediaStore 사진 묶음 및 fingerprint·volumeVersion과 일치하는 항목만 유효하게 표시한다. 권한 철회·파일 변경·묶음 변경 시 기존 기록을 그대로 실제 정리 대상으로 사용하지 않는다.
- 저장된 '정리 후보'는 곧바로 파일을 선택하거나 이동하지 않는다. 검토함 하단 **정리 후보 확인**을 누른 뒤 다시 유효성·보호·최소 한 장 보존·500개 선택 제한을 적용한다.
- 원본 이동은 기존 MainActivity revalidate / Android 시스템 휴지통 승인 절차를 반드시 거친다.
- 검토 기록 초기화에는 사용자 확인을 요구하며 원본/휴지통 기록은 삭제하지 않는다.
- 기존 앱 id, 서명, Play 트랙, 버전, 파일 포맷, 임의 자동 삭제는 변경하지 않는다.

## 검증
1. 순수 Kotlin 유닛 테스트: 유효 상태, 다른 fingerprint/version, 권한에 따른 그룹 제외, 보호 파일, 최소 한 장 보존, 완료/미완료.
2. Android Room 계측: 새 테이블 저장, 기존 카탈로그 리프레시 뒤 보존, 검토 기록 초기화와 보호 정책의 분리.
3. Android Compose 계측: 모바일 명시적 상태 선택과 정리 호출 분리, 초기화 확인, 태블릿 2열, 보호·즐겨찾기 제외.
4. 기존 사진 분석/12-A 비교/12-B 추천/실제 휴지통 승인/보호·즐겨찾기 회귀.
5. Android 36 5개 화면 환경 × 라이트/다크, 리뷰 목록/상세 2장씩 실제 캡처와 매니페스트·이미지 감사를 추가했다.
6. 모두 통과한 동일 PR HEAD만 main에 병합하며, 이번 단계에서 신규 Google Play 제출은 수행하지 않는다.

## 제한 및 수동 QA
- 미디어 접근 권한이 부분적으로 제한되면 접근 가능하고 현재 분석된 사진만 진행률에 포함한다. 되돌릴 수 없는 파일 삭제나 상태 자동 확정은 하지 않는다.
- 실제 삼성 휴대폰·태블릿·폴더블, 1,000장 이상 대량 그룹, HEIC/RAW/다양한 MP4, 화면 회전, 160% 글꼴, 시스템 휴지통 취소·승인·복원은 실기기 QA에서 추가 확인한다.
- '남김'은 검토 기록의 분류이며 원본 파일을 별도의 영구 삭제 방지 목록으로 등록하는 행위가 아니다. 보호가 필요하면 기존 '보호' 기능을 사용한다.
