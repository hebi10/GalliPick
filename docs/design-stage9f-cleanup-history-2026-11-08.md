# GalliPick 9-F — 확인된 정리 기록 저장·조회·삭제

기준: 9-E PR #65 main 병합, 2026-11-08.

## 범위
- 정리 탭 > 정리 기록 보기. 기존 홈·파일·정리·설정 4개 상위 탭 변경 없음.
- MediaStore.createTrashRequest로 사용자가 이동/복원을 승인한 이후, MediaStore 재조회와 TrashOutcomePolicy 분류가 완료된 **성공 건수**만 새 Room cleanup_history 테이블에 저장.
- 1회 Android 승인 요청당 1개의 로컬 기록. 요청 식별자로 중복 기록 방지, 실제 확인 완료 수와 용량, 요청 수, 작업 유형(MOVE_TO_TRASH/RESTORE), 기록 시각 저장.
- 일부 성공 / 일부 상태 불명확 시 **확인 완료 건수와 용량만 기록**, 요청 총건수와 함께 부분 완료 표기. 승인 취소, 실패, 전부 상태 불명확이면 기록을 만들지 않음.
- 기록에 미디어 URI, 파일명, 이미지 원본, SHA256 또는 pHash를 저장하지 않음. 다른 앱이나 서버로 데이터를 보내지 않음.
- 개별 기록 삭제/전체 기록 삭제는 Room cleanup_history만 변경. media_cache, 사용자 원본, 휴지통, 보호·즐겨찾기 상태는 불변.
- 비공개 분석 캐시 초기화, MediaStore 접근 권한 제한, 미디어 목록 새로고침에 의해서도 이력은 삭제되지 않음.
- Room 스키마 4→5 명시적 마이그레이션. 기존 1→2→3→4 경로 유지, 자동 파괴성 초기화 없음.
- 휴지통 이동 용량은 휴지통으로 옮겨진 파일의 크기이며 실제 확보 공간이 아님.

## 검증
- JVM: 확인 완료/부분 완료/복원/취소/불명확/상태 불일치 기록 금지.
- Android Room: 동일 요청 ID 재진입 시 중복 차단, 최근순 정렬, 개별/전체 기록 삭제, 미디어·보호·중복 SHA256 캐시 불변, 접근 가능 파일이 없을 때도 기록 유지.
- Android Compose: 빈 기록, 부분 확인 메시지, 개별 기록 삭제 확인/취소, 전체 기록 삭제 확인.
- Android verification + Android device tests의 최종 PR HEAD 둘 다 성공한 뒤 main 병합. Play 서명·버전·트랙 변경/자동 배포 없음.
