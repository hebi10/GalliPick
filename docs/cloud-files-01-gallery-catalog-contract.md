# CLOUD-FILES-01 — 로컬·클라우드 통합 카탈로그 및 폴더 메타데이터

기준: `main` 303191349397763131bb339ccf0130ae53046885  
상태: 데이터 계약·순수 목록 모델 구현. 파일 탭 UI 연결·스트리밍·운영 Functions 배포는 후속 단계.

## 1. 보존 조건

- `MediaRepository`는 Android MediaStore의 로컬 전용 카탈로그를 계속 소유합니다.
- `CloudOriginal`은 계정별 서버 검증 원본입니다. 절대로 임의의 `content://` MediaStore URI를 생성해 로컬 파일로 위장하지 않습니다.
- 통합 목록(`UnifiedGalleryCatalog.kt`)은 표시 전용입니다. 기존 휴지통·중복 검사·보호·정리 작업 입력을 변경하지 않습니다.
- `CloudGallerySnapshot.accountUid`가 현재 로그인한 UID와 일치하지 않으면 클라우드 목록을 전부 숨깁니다.
- 기존 백업은 서버 메타데이터가 없어도 보관함·복원이 유지됩니다. 폴더가 없는 원본은 UI 적용 시 `미분류`로 표현합니다.

## 2. 서버 메타데이터 계약

`beginBackup`에는 기존 `sha256`, `sizeBytes`, `mimeType`, `displayName` 외에 선택적으로 아래 필드를 전송합니다.

| 요청 필드 | 설명 | 제약 |
| --- | --- | --- |
| `sourceFolder` | 원본 기기의 MediaStore 상대 폴더 | 상대 경로, NFC 정규화, 최대 160자 / 8개 경로 단위, 절대경로·역슬래시·`.`·`..`·제어문자 거부 |
| `capturedAtMs` | 실제 원본 촬영 시간 | 양의 안전한 정수, 없으면 생략 |
| `width`, `height` | 미디어 해상도 | 양의 정수, 최대 100,000 |
| `durationMs` | 동영상 길이 | 양의 안전한 정수, 없으면 생략 |

서버 `listBackups` 및 `getBackupDownload`에는 존재하는 메타데이터만 반환합니다.

- `sourceFolders` — 동일 검증 원본을 백업한 출처 폴더의 정규화된 배열(최대 8개)
- `capturedAtMs`, `width`, `height`, `durationMs` — 최초 업로드 예약 메타데이터
- 기존 원본은 메타데이터 부재를 허용하며 검증 날짜 `verifiedAtMs`를 촬영 날짜로 오인하지 않습니다.
- 새 메타데이터는 Storage 객체 이름·해시·세대·바이트 수를 변경하지 않습니다.
- 동일 계정에서 동일 SHA-256·크기 원본을 다른 폴더에서 재백업할 경우 원본 바이트는 복제하지 않고 `sourceFolders`만 트랜잭션으로 추가합니다. 저장량 과금·원본 무결성은 기존 정책 유지.
- 현재 1개 원본 객체의 출처 폴더 목록만 추적합니다. 사용자가 직접 생성하는 클라우드 폴더, 이름 변경, 파일 이동을 위한 별도 소속 컬렉션은 후속 기능 단계에서 추가합니다. 이 1단계는 원본 삭제·폴더 CRUD를 수행하지 않습니다.

## 3. 통합 갤러리 계층

- `GalleryEntryKey.Device(uri)` — 기기 전용 파일 키
- `GalleryEntryKey.Cloud(accountUid, uploadId)` — 클라우드 전용 또는 양쪽 보관 파일 키
- `GallerySource.DEVICE / CLOUD / BOTH` — 표시 출처
- `VerifiedGalleryMatch` — 전체 원본 SHA-256 검증 결과와 원본 `fingerprint`, `volumeVersion`을 함께 보유

이름·폴더·시간이 유사하다는 이유만으로 기기 파일과 클라우드 파일을 합치지 않습니다. 별도 전체 원본 바이트 검증의 유효한 증거가 있을 때만 `BOTH`로 합치며, 기기 파일이 사라지면 동일 클라우드 키가 그대로 `CLOUD`로 유지됩니다.

## 4. 안전한 단계별 적용 순서

1. 현재 서버·클라이언트 회귀 테스트에 새 메타데이터 계약 및 레거시 호환 테스트 추가.
2. Firebase 개발 환경 Functions를 **명시적 승인 및 테스트 후** 배포(이번 PR에서 자동 배포 금지).
3. 신규 클라이언트에서 폴더·촬영 메타데이터를 전송하고, 서버 응답을 optional 필드로 해석.
4. 다음 CLOUD-FILES-02에서 기존 파일 탭에 소스 필터·통합 그리드를 연결. 운영 파일 정리 대상은 로컬 전용으로 유지.
5. 다음 CLOUD-FILES-03/04에서 사진 뷰어·동영상 스트리밍을 별도로 구축.

## 5. QA

- Node: 기존 업로드·복원·다운로드 권한 회귀, 동일 원본 재백업의 폴더 병합, 제한 검증, 레거시 목록.
- Kotlin: 계정 간 데이터 노출 방지, 검증된 동일 바이트 파일만 병합, 버전 변경 시 병합 취소, 로컬 삭제 뒤 안정된 클라우드 키, 폴더 경로 검증.
- 현재 Play 시험 한도는 파일당 64MiB, 서버 승인 계정당 최대 1GiB로 유지. 50/200GB 상용 요금제와 무관.
- 본 단계는 서버 운영 데이터 마이그레이션을 직접 실행하지 않습니다. 레거시 항목의 `sourceFolders` 누락은 기본값으로 수용하고 재업로드 시 갱신할 수 있습니다.
