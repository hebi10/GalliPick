# GalliPick 9-E — 선명도 확인 후보 분석 및 비교

기준: 9-D 병합 main `f7ee95ae5a8fe7b0a08f5fb98c80ec38b4ba28cc` / 2026-11-08.

## 구현
- 기존 기기 내 PhotoAnalysisWorker에 128×128 그레이스케일 경계(라플라시안) 분산 측정 추가. pHash는 32×32 입력으로 동일 알고리즘 유지.
- 수치가 낮은 사진은 **선명도 검토 후보**로만 표시. 선명도는 사진 품질의 확정 판정이나 삭제 근거가 아님.
- 128×128 샘플의 명도 분산 225 이상, 명도 범위 45 이상, 경계 분산 20 이하, 원본 가로·세로 모두 640픽셀 이상에서만 보수적으로 후보 추천.
- 균일한 색/저대비 사진, 샘플 디코딩 실패, 파일 변경, 권한 제한은 추정 불가로 제외. 인물 사진의 의도적 아웃포커싱·야간/예술 사진은 오탐지가 가능함을 UI에 명시.
- Room photo_perceptual_hash에 nullable `sharpnessScore` 추가, 데이터베이스 3→4 명시적 마이그레이션. 기존 해시에서 점수가 없으면 재분석 대상으로 표시, 새 분석은 동일 WorkManager의 이어서 처리·일시정지/재개/토큰·fingerprint·볼륨 버전 검증을 재사용.
- 기존 유사 사진 결과와 달리 비교할 다른 사진이 없는 단독 흐림 후보도 목록에서 원본 외부 앱 열기 가능.
- 유사한 사진 묶음이 있을 때만 기존 다중 남김·사진 비교·휴지통 승인 UI로 연결. 단독 후보는 새 자동 삭제·일괄 정리 버튼 없음.
- 보호·즐겨찾기·보호 폴더의 후보는 목록에서 제외. 검토 후보 수치는 용량 확보 예상치가 아님.

## 검증
- JVM: 균일·부드러운 그라데이션·명확한 고주파 경계·잘못된 입력, 보호/즐겨찾기/폴더/소형 이미지/점수 누락/후보 정렬/비교 가능성.
- Room Android: 선명도 값 저장 및 볼륨 버전 변경 시 캐시 무효화.
- Compose Android: 결과 화면·단독 후보 원본 확인·선택 없는 상태의 휴지통 미노출·유사 그룹 비교 클릭.
- 실제 기기 화면·과노출/야간/배경 흐림/스캔 사진 등 대규모 오탐률 검증은 9-G에서 추가.
